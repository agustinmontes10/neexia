## Commands

- `npm run dev` — start the dev server (Turbopack). Default port is 3000; if another local project already holds it, Next.js auto-selects the next free port (e.g. 3001) and prints the actual URL in the terminal — check the log rather than assuming 3000.
- `npm run build` — production build.
- `npm run start` — serve the production build.
- `npm run lint` — ESLint (flat config: `eslint-config-next` core-web-vitals + typescript rules).
- `npx tsc --noEmit` — type-check; there is no dedicated `typecheck` script.
- No test runner is configured in this project.

## Architecture

This is a Next.js App Router marketing site for Neexia (an AI agency), replicated from a Claude Design mock ("Landing page para Neexia", fetched via the design MCP). The main experience is the single-page landing at `/`; the other routes are per-service detail pages at `/servicios/[slug]` and per-project detail pages at `/casos/[slug]`.

- **Visual direction ("calm" redesign, branch `redesign/calm`):** inspired by the *style* of a Figma Motion landing (calm, airy, two-tone headings, glass cards over an atmospheric backdrop, a single accent color) — but not its content or imagery. Neexia's own replacement for that reference's landscape photo is `Atmosphere.tsx`: a warm CSS mesh gradient (peach/amber/cream/dusty rose blobs drifting via `atmo-a/b/c` keyframes), the Neexia X mark as a diffuse light source, and a `.grain` overlay. Variants: `dawn` (hero), `soft` (cards/frames — deliberately has **no base fill**, just the glows over the page background, because a filled peach base hurt legibility of the card content), `dusk` (currently unused). The parent must be `relative` and clip it. The root has `isolation: isolate` on purpose: without it the grain's `mix-blend-mode: soft-light` blends against whatever compositing layer the browser happens to use, so cards changed look a few seconds after the reveal finished. The blurred X wraps the masked element in a separately blurred div on purpose — CSS applies `filter` before `mask` on the same element, which would leave the X crisp. The accent is `brand` = `#ffbd59` (light orange) with `brand-light` = `#FF8336` as its hover — the owner swapped these two on purpose, so the token names no longer match lightness; don't "fix" them. Brand buttons use `text-ink`, not white. The reference's lime was explicitly rejected. There is no photography anywhere by design.
- `app/page.tsx` composes the landing page by stacking section components in order: `Nav` (with `overlay`, floating over the hero), `Hero`, `Intro`, `Servicios`, `Proceso`, `Casos`, `Faq`, `CtaFinal`, `Footer` (all in `app/components/`). The root wrapper here must **not** get `overflow-x-hidden` (or any non-`visible` overflow) — it becomes the nearest scroll container and silently breaks `position: sticky`, which `Proceso.tsx` depends on. Scope any overflow-clipping needs to the individual component instead.
- Design tokens live in `app/globals.css` (`@theme inline`, Tailwind v4 CSS-first, no `tailwind.config.js`): `bone` (#f4f3ef page bg), `ink` (#161616 text), `mute` (gray first line of two-tone headings), `body` (paragraph gray), `line` (hairline borders), plus brand `brand` / `brand-dark` / `brand-light`. Utilities `.glass` (frosted card), `.grain`, `.x-mark` (alpha mask of `public/X.svg`). Headings are light (`font-normal`) with tight negative tracking — no `font-bold`/`extrabold` in the redesign. `SectionHeading.tsx` renders the two-tone heading (`muted` + `strong`, optional `inline`).
- `Hero.tsx`: full-viewport `Atmosphere`, headline with inline overlapping tool "pills" (WhatsApp/ChatGPT/Gmail) wrapped in `whitespace-nowrap` with "la IA" so they never orphan on mobile, then the subtitle paragraph and the two CTAs — nothing else. The three glass cards that used to sit at the bottom (diagnóstico → WhatsApp, the 5 services as icon links, and `stats[0]` with an SVG ring) were removed by the owner for a calmer hero; don't bring them back (the `ring-fill` keyframe and `stats` data are now unused but kept). The block is flex-centred in the full-viewport section: top padding only clears the overlay nav, and a slightly larger bottom padding lifts it a touch above the geometric centre (optical centre); on `lg` paddings, heading size and gaps are svh-based clamps so it stays one screen. Tool brand marks come from `ToolIcon.tsx` (Iconify artwork copied verbatim; gradient ids are rewritten per instance with `useId()` because the same icon can render more than once on a page). The old `ToolsBanner` diagram, `CursorGrid`, `WorkflowDemo` and `Resultados` strip were deleted in the redesign — see git history if needed.
- `Intro.tsx` ("Lo que hacemos, en tu día a día."): explains what Neexia does through four everyday pains in the owner's own words (`scenes` in `landing-data.ts` — organised by pain, not by industry; `where` lists example industries only, mixing several so nobody feels excluded). Layout, built to fit one viewport on desktop (heading → service link): heading and intro paragraph on one row (no CTA button there — the owner found it distracting — and no closing "¿Lo tuyo no está acá?" line either, also removed by the owner), a browser-like window: the atmosphere frame with a tab strip on top (one tab per scene, `Scene.tab` + a tool icon as "favicon"; tabs are content-width below `sm` so all four fit at 375px). The active tab has no fill so the window background shows through it, and a huge `box-shadow` in the strip colour paints the rest of the strip around its rounded top (the strip's `overflow-hidden` clips it) — keep the spread larger than the widest strip or the far end goes unpainted. A soft white fill sweeping left → right across the active tab shows the time left — revealed with `clip-path` in the `tab-progress` keyframe, not `scaleX`, which squashes the rounded corners. Hovered inactive tabs get a full-size, same-shape lighter fill (and hide their separators). Below the tabs, the active quote (smallish, centred) and its visual; on `lg` the section is `.screen-section` and the window is `flex-1` (min 340px, wrapper capped at 660px) with the visual in `.fit-zoom`, and under it the one-line `withUs` + service link. `Scene.where` is currently not rendered. Scenes auto-advance every `ADVANCE` ms (the tab fill's `animationend` drives it), paused on hover and until in view, and off under reduced motion. Each visual in `SceneVisual.tsx` is deliberately big and simple (2–3 large pieces), driven by the registered custom property `--scene` (`@property` in `globals.css`, transitioned 0 → 1 on mount); pieces derive a staggered `--pi` via `at()`. Rejected along the way, don't bring back: an exploded isometric layer stack and a scroll-driven "chaos → order" panel (broke the calm / didn't explain what we do), a click-only quote list with dense UI mock-ups and a "Hoy / Con Neexia" text block (cramped, scenes hidden behind clicks). The previous illustrative dashboard is kept, unused, in `IntroDashboard.tsx` (restore instructions in `Intro.tsx`).
- Copy/content is centralized in `app/lib/landing-data.ts` as typed arrays (`services`, `steps`, `cases`, `stats`, `scenes`). Edit content there, not inside the section components. `Stat.value` / `CaseStudy.metric` strings must keep the `[+-]?number + suffix` shape (`-5h`, `3x`, `24/7`) because they run through `AnimatedMetric.tsx`. FAQ copy lives separately in `app/lib/faq-data.ts` and is also emitted as `FAQPage` JSON-LD (`faqSchema` in `structured-data.ts`) by `Faq.tsx`; answers stay in the DOM when collapsed (grid-rows animation) so crawlers see them.
- `Servicios.tsx` is a static bento grid (3 + 2 cards), each card linking to `/servicios/[slug]` with the service's `ServiceVisual` (`bare` mode) over an `Atmosphere`. It replaced the old auto-advancing tabs. `ServiceVisual` without `bare` renders its own soft-atmosphere frame (used on the service detail page). `ServiceIcon.tsx` (`diagnostic`/`automation`/`agents`/`chat`/`web`) is switched on `Service.icon`.
- `Proceso.tsx` ("Cómo trabajamos"): on `lg+` the section is `steps.length * VH_PER_STEP + VH_TAIL` vh tall (50/30, shortened from 70 per step so it doesn't drag) with a `sticky top-0 h-screen` inner, and scroll progress through it selects the active step. A 2px track left of the step list fills in `brand` with that progress (written to the DOM via `barRef`, not state), and each step card is clickable (a button inside the `h3` whose `::after` covers the card) — `goToStep` scrolls to the middle of that step's range — the step card turns white and the framed visual on the left cross-fades (one hand-built card per step in `VISUALS`, indexed by position, so adding a step means adding a visual). Below `lg` it's a plain stack of cards with their own visuals.
- `Casos.tsx`: same visual language as the Servicios cards (owner's choice after rejecting photo/white story cards): a bento (`lg:grid-cols-3`; `webScroll` cases span 2 columns, the chat 1; single column below `lg`) of `CaseStage`s (exported from `CaseVisual.tsx`, also used on the case page): a soft `Atmosphere` surface with a hairline ring, and the visual filling its height, standing on the bottom edge and cropped (`-mb-3` so the hover lift never shows a gap), 420/480/500px tall; a role badge, and below it the counting metric, label and business type. Visuals: `webScroll` (a browser window panning a full-page screenshot `CaseStudy.image` like a screen recording — `page-scroll` keyframe on `background-position`, ends at the top; screenshots are pre-converted to ~720px-wide WebP with sharp) and `whatsappChat` (`CaseStudy.chat` played bubble by bubble with an "escribiendo…" state, looping; supports voice notes via `audio: true`). On `lg` the quote slides in as a glass overlay on hover (no blur, so the animation stays visible); the full quote lives on the case page.
- `CtaFinal.tsx`: open closing CTA with no card (owner rejected the dark-glass-on-dusk banner) — two-tone heading centered over a soft atmosphere that is radially masked via inline `style` so it has no edges. Shared by the home and detail pages.
- **Viewport fit (lg+):** Hero, Intro, Proceso (sticky panel) and Casos are meant to be seen whole, so they fit one screen down to ~580px tall: Intro/Casos use `.screen-section` (globals.css: `min-height: 100svh`, centred, svh-based padding — unlayered, so no `lg:py-*` next to it), and their inner sizes are `clamp(…, …svh, desktop value)`. Servicios, FAQ and CTA deliberately are **not** forced into 100vh (the owner rejected squeezed Servicios cards); they only get svh-relative padding/heights. Headings scale with `clamp(min, min(vw, svh), desktop size)` in `SectionHeading`, so a 1920×1080 desktop looks as before and notebooks shrink proportionally. `.fit-zoom` shrinks illustrations on short viewports via `zoom` (affects layout, unlike `scale`).
- `Reveal.tsx` is the reveal-on-scroll wrapper (IntersectionObserver toggling `.reveal`/`.reveal-visible`; the reveal fades up *from a blur*). `globals.css` has a global `prefers-reduced-motion` override that collapses all animations/transitions to their end state — every `@keyframes` there is authored so its final frame is a sensible static state (fade/blur-ins end visible, flow dots end hidden, atmosphere blobs return to origin, ring fill ends at its target); keep that invariant when adding keyframes.
- **Animation performance:** looping decorations used to keep a 4×-throttled phone CPU ~98% busy from anywhere on the page. Two rules now: (1) `OffscreenAnimationPause.tsx` (mounted once in `layout.tsx`) toggles `data-offscreen` on every off-screen `<section>`, and a rule in `globals.css` pauses the **infinite** `animate-*` classes inside — add any new looping class to that list, and never add one-shot entry animations to it (paused at frame 0 = invisible); infinite loops must keep first frame == last frame so pausing at the start is invisible. (2) Animate only `transform`/`opacity`: `flow-dot-x/y` move a full-track wrapper (`absolute inset-0`, dot pinned at its edge) by `translate(100%)` instead of animating `left`/`top`, and `ring-pulse` is a `brand-light` disc *behind* the opaque node scaling to `--pulse-scale` instead of an animated `box-shadow`. `web-resize` still animates `width` on purpose (the mock reflows like a responsive site) and is the one remaining main-thread loop. The hero `<h1>` and paragraph deliberately have **no** entry animation: anything painted at `opacity: 0` isn't an LCP candidate, so while they faded in, LCP fell on the tiny nav logo (PageSpeed mobile: LCP 3.1s, Speed Index 4.3s, score 91) — don't put `blur-in`/`reveal` back on them. Measure with PageSpeed Insights (Google's infra), not local Lighthouse: on this Windows machine a cold-GPU first-paint stall in each fresh Chrome drags the simulated mobile score to ~50–60 with TBT in seconds (PageSpeed: TBT 10ms), and it swings ±8 points between identical runs.
- `Nav.tsx` is a client component: centered links on `md+`, a full-screen menu below `md`. Pass `overlay` only where the first section is a full-bleed hero (the home page); detail pages use the default in-flow nav. Once that bar scrolls away, a fixed pill (logo, links on `md+`, "Hablemos", burger below `md`) takes over — denser than `.glass` on purpose (`bg-bone/[0.82]` + stronger blur) because at 42% white the big headings behind read through the links; a full-width bar below `md` (a fit-content capsule looked tiny on phones), a capsule on `md+`: hidden on scroll down, shown on scroll up, kept visible ~1.5s after a click on its own links (`holdPill`) so it doesn't vanish during the smooth scroll; it's `inert` while hidden. On `/` it highlights the section crossing 40% of the viewport with a sliding white fill (measured from `[data-section]` links). "Industrias" was removed from the nav on purpose (and from the Footer too, by the owner — the pages stay in the sitemap and llms.txt, with no inbound links from the site). Anchor scrolling: `html { scroll-behavior: smooth; scroll-padding-top: 2rem }` in `globals.css` (replaces per-section `scroll-mt-8`; `Proceso` uses `lg:-scroll-mt-8` so its sticky panel lands flush at the top) plus `data-scroll-behavior="smooth"` on `<html>` so route changes stay instant (Next 16).
- `app/servicios/[slug]/page.tsx`, `app/casos/[slug]/page.tsx` and `app/diagnostico/page.tsx` use the same tokens (bone background, light headings, pill buttons) and share `Nav`/`CtaFinal`/`Footer`. Service/case pages are statically generated via `generateStaticParams` (`notFound()` for unknown slugs); case pages cross-link to services via `CaseStudy.relatedServices`.
- `/industrias` + `/industrias/[slug]` (data in `industries-data.ts`, `relatedCase` must be a real `cases` slug) and `/glosario` (`glossary-data.ts`) came from the SEO Fase 2 on `main` and still use the **old** styling (bold headings, `bg-brand text-white` buttons) — pending a pass to the calm tokens. `/diagnostico` is **hidden** (noindex, out of sitemap/llms.txt, no inbound links): the Hero diagnóstico card opens WhatsApp instead; the route, quiz and API stay intact for re-enabling.
- Nav/CTA links to the landing sections use root-relative hash links (`/#servicios`, `/#proceso`, `/#casos`, `/#faq`, `/#contacto`) via `next/link`, not bare `#anchor`s — required so they resolve from detail pages too. Keep these `id`s in sync with `Nav.tsx`, `Footer.tsx` and the CTA links.
- `public/X.svg` is Neexia brand artwork (a stylized orange "X" mark), **not** the X/Twitter logo — used as the `.x-mark` mask (blurred light source in `Atmosphere`, small crisp marks in the hero card and Intro panel). `public/LogoNeexiaBlanco.svg` is the white wordmark; `app/opengraph-image.tsx` reads it via `node:fs` at that path, so renaming/moving it breaks the build.
- Dev gotcha (recurring on this Windows setup): Turbopack keeps serving a stale compiled `globals.css` — edits to tokens in `globals.css` and *new* Tailwind class names used in components (e.g. a never-before-used `leading-[1.05]`) don't show up in the browser, with no error in the log. Fix: stop the dev server, delete `.next`, restart. `npm run build` is unaffected. Verify with `getComputedStyle` before assuming a styling change is wrong.
